2. Detailed Practical List

Practical 1: Project Initiation, Requirement Analysis, Sitemap, Wireframe, and GitHub Setup

Problem Definition: Initiate the semester-long StudentHub portal by identifying the problem scope, user roles, key modules, navigation flow, and minimum 10 pages. Create a sitemap, low-fidelity wireframe, project folder structure, README file, and GitHub repository.

Key Questions / Analysis / Interpretation:

  1. What is URL and parts of URL?
  2. How does HTML file processed in web browser?
  3. How will page navigation flow be managed among all HTML pages?
  4. How will GitHub commits be maintained after each practical?

Key Skills to be Addressed: Requirement analysis, sitemap design, wireframing, Git/GitHub, README writing, folder structuring.

Applications: Web application planning and maintainable project setup.

Learning Outcome: Students will be able to analyze requirements and prepare a structured project foundation before implementation.

CO Mapping: CO1

Dataset/Test Data: N/A; design artefacts only.

Tools/Technology to be Used: VS Code, Draw.io/Figma, Git, GitHub.

Total Hours: Implementation: 4 hours | Total engagement: 4 hours.

Post Laboratory Work Description: Submit project functional requirements, sitemap, wireframe screenshots, GitHub repository link, and README.md.

Evaluation Strategy Including Viva: Requirement clarity, sitemap completeness, role definition, repository structure, and viva on project scope.

Advanced/Intermediate Extension: Intermediate: Create responsive wireframes in Figma. Advanced: Prepare ER diagram and REST-style route plan for future backend modules.

Practical 2: Semantic HTML5 Pages with Accessibility-Ready Structure

Problem Definition: Develop static HTML5 skeletons for at least 10 Student Hub pages such as Home, About, Register, Login, Dashboard, Events, Profile, Contact, Admin, FAQ, and Feedback. Use semantic tags and accessibility-friendly structure.

Key Questions / Analysis / Interpretation:

  1. Are semantic tags such as header, nav, main, section, article, aside, and footer used properly?
  2. Are form labels, headings, image alt text, and navigation links accessible?
  3. Is the page structure consistent across all pages?

Key Skills to be Addressed: HTML5 semantic elements, accessibility basics, page linking, navigation menu, content hierarchy.

Applications: Static website foundations and accessible UI design.

Learning Outcome: Students will create clean, linked, and accessibility-ready HTML page structures.

CO Mapping: CO1, CO2

Dataset/Test Data: Sample page content for student portal.

Tools/Technology to be Used: VS Code, HTML5, browser accessibility inspection tools.

Total Hours: Implementation: 4 hours | Total engagement: 6 hours.

Post Laboratory Work Description: Submit static page screenshots, source code, and accessibility checklist.

Evaluation Strategy Including Viva: Semantic correctness, page linking, accessibility readiness, and code readability.

Advanced/Intermediate Extension: Intermediate: Add breadcrumb navigation. Advanced: Add skip-to-content link and keyboard-friendly navigation.

Practical 3: Responsive UI Design using CSS Grid, Flexbox, and Bootstrap/Tailwind

Problem Definition: Design responsive layouts for Home, About, Registration, Dashboard, and Events pages using CSS Grid and Flexbox. Optional to use CSS framework such as Bootstrap or Tailwind. Ensure mobile-first responsiveness.

Key Questions / Analysis / Interpretation:

  1. How does the layout adapt for mobile, tablet, and desktop screens?
  2. Which layout technique is used and why?
  3. Are typography, spacing, colors, and contrast readable?
  4. Is the framework used consistently without unnecessary inline CSS?

Key Skills to be Addressed: CSS3, media queries, Flexbox, Grid, Bootstrap components, responsive design.

Applications: Multi-device web interface design.

Learning Outcome: Students will design a professional, responsive, and reusable UI layout.

CO Mapping: CO2

Dataset/Test Data: N/A; UI design only.

Tools/Technology to be Used: HTML5, CSS3, Bootstrap, browser responsive mode.

Total Hours: Implementation: 4 hours | Total engagement: 6 hours.

Post Laboratory Work Description: Submit screenshots for mobile, tablet, and desktop views.

Evaluation Strategy Including Viva: Responsiveness, framework usage, visual consistency, and CSS organization.

Advanced/Intermediate Extension: Intermediate: Add Contact and Feedback pages. Advanced: Create reusable layout components using JavaScript libraries such as jQuery.

Practical 4: JavaScript DOM Manipulation, Event Handling, and UI Interactivity

Problem Definition: Add dynamic UI components such as collapsible FAQ, modal popup, image/content slider, notification banner, hamburger menu, and light/dark theme switcher using JavaScript.

Key Questions / Analysis / Interpretation:

  1. How are DOM elements selected and modified?
  2. Are event listeners attached correctly?
  3. Is localStorage used for remembering theme choice?
  4. Does interactivity improve usability without breaking accessibility?

Key Skills to be Addressed: DOM selection, event handling, class manipulation, localStorage, basic animation.

Applications: Interactive dashboards and dynamic frontend behaviour.

Learning Outcome: Students will apply JavaScript to enhance user experience and client-side interactivity.

CO Mapping: CO3, CO4

Dataset/Test Data: Static FAQ/event content.

Tools/Technology to be Used: JavaScript ES6+, HTML5, CSS3, browser dev tools.

Total Hours: Implementation: 4 hours | Total engagement: 6 hours.

Post Laboratory Work Description: Submit live demo and source-code explanation.

Evaluation Strategy: DOM logic, event handling correctness, usability, and browser console testing.

Advanced/Intermediate Extension: Intermediate: Add transition effects to cards/buttons. Advanced: Store user UI preferences in localStorage and restore them on page load.

Practical 5: Registration Form with Frontend Validation and User-Friendly Error Handling

Problem Definition: Create a student registration form with HTML5 input types and JavaScript validation for name, email, mobile number, password, confirm password, course, year, gender, and terms acceptance. Use Regular Expression for validations.

Key Questions / Analysis / Interpretation:

  1. Are correct input types and attributes used?
  2. Are validation errors displayed near the relevant fields?
  3. Is password strength checked?
  4. Is the form accessible using keyboard and screen-reader-friendly labels?

Key Skills to be Addressed: HTML forms, JavaScript validation, regular expressions, password strength meter, UX error messages.

Applications: Registration and data-entry systems.

Learning Outcome: Students will design accessible forms with robust client-side validation.

CO Mapping: CO1, CO3

Dataset/Test Data: Valid and invalid sample registration inputs.

Tools/Technology to be Used: HTML5, JavaScript ES5/ES6, browser dev tools.

Total Hours: Implementation: 4 hours | Total engagement: 6 hours.

Post Laboratory Work Description: Submit validation test cases with screenshots for valid and invalid inputs.

Evaluation Strategy Including Viva: Input coverage, validation accuracy, error handling, and code walkthrough.

Advanced/Intermediate Extension: Intermediate: Add real-time validation on keyup/change events. Advanced: Add custom CAPTCHA using Canvas.

Practical 6: Rendering External JSON Data using Fetch API, Search and Filter

Problem Definition: Display event lists, student profiles, notices, or FAQs from external JSON files using Fetch API. Implement dynamic rendering, search, filter, sorting, and pagination.

Key Questions / Analysis / Interpretation:

  1. How is JSON fetched, parsed, and rendered?
  2. Which array methods are used for search, filter, sort, and pagination?
  3. How are loading and error states handled?
  4. How is modularity maintained in JavaScript files?

Key Skills to be Addressed: JSON, Fetch API, arrays, map/filter/sort, modular JavaScript, pagination logic.

Applications: Dynamic data rendering in modern web applications.

Learning Outcome: Students will consume external JSON data and render reusable frontend views.

CO Mapping: CO3, CO4

Dataset/Test Data: events.json, students.json, faqs.json with at least 15 records each.

Tools/Technology to be Used: JavaScript ES6+, JSON, HTML5, CSS3.

Total Hours: Implementation: 4 hours | Total engagement: 6 hours.

Post Laboratory Work Description: Submit JSON files, rendered views, and test screenshots for search/filter/pagination.

Evaluation Strategy Including Viva: JSON parsing, array logic, UI rendering, error handling, and console testing.

Advanced/Intermediate Extension: Intermediate: Add dependent dropdowns for country/state/city. Advanced: Cache the latest JSON response in localStorage for offline-like display.
